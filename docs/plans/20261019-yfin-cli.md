# yfin CLI: native-image command-line tool distributed through Homebrew

## Overview
- Build `yfin`, a command-line tool over the published `yfin-core` library. It is compiled to a
  GraalVM native image and installed with `brew install andreygrigoriev/tap/yfin`.
- Humans and scripts both use it: tables by default, `--format csv|json` for pipelines, stable
  exit codes, data on stdout and diagnostics on stderr.
- Broad v1 coverage: one command per public `Ticker` accessor, plus search, lookup, screener,
  sector, industry, market and the market-wide calendars.
- It lives in a **separate repo** `andreygrigoriev/yfin-cli` and depends on `yfin-core` from
  Central, so CLI and library releases are independent. A second repo,
  `andreygrigoriev/homebrew-tap`, holds the formula.
- This plan sits in the library repo only because `yfin-cli` doesn't exist yet. Task 1 moves it
  to `yfin-cli/docs/plans/`. All paths below are relative to the `yfin-cli` repo root unless
  they're marked `(yfin)`.

## Context (from discovery)
- Library: `io.github.andreygrigoriev:yfin-core:0.2.1` on Central, JPMS module
  `io.github.andreygrigoriev.yfin`. It exports `yfin`, `yfin.model`, `yfin.request`, `yfin.spi`
  and `yfin.exception`.
- Entry points: `YFinance` (builder: `transport`, `cache`/`cacheDir`, `maxRetries`, timeouts;
  `lookup`, `*Calendar`, `sector`, `industry`, `market`), `Ticker` (around 45 accessors),
  `Tickers` (multi-symbol `history`, `news`), `Search`, `Screener`, `Sector`, `Industry`,
  `Market`, `FastInfo`.
- Request types: `HistoryRequest`, `Period`, `Interval`, `Frequency`, `MarketRegion`, `NewsTab`,
  `LookupType`, `CalendarRequest`, `EarningsCalendarRequest`, `SortField`.
- Exceptions: `YFinanceException` → `YFSymbolNotFoundException`, `YFRateLimitException`,
  `YFAuthException`, `YFTransportException`, `YFDataException`, `YFDownloadException`.
- `YFinance` defaults to a `FileCache` in `$XDG_CACHE_HOME/yfin` (or `~/.cache/yfin`), so the
  cookie and crumb persist across CLI invocations.
- `yfin-core-0.2.1-tests.jar` is on Central. It contains `io.github.andreygrigoriev.yfin.testing.FakeTransport`
  and the recorded fixtures under `fixtures/<endpoint>/<case>.json` (calendar, chart, earnings,
  industry, isin, lookup, market, news, options, quote, quoteSummary/{analysis,funds,holders,secfilings},
  screener, search, sector, session, shares, timeseries/{peg,valuation}).
- Library conventions to copy: Spotless (palantir-java-format), `package-info.java` with
  `@NullMarked` everywhere, javadoc lint `all,-missing`, lookup tables as Java constants (not
  resources), no reflection in our own code, and the `-Pnative test` profile.
- Test setup to copy (from the yfin CLAUDE.md): `fake.onGet("").respond(404, "not found")`,
  `fake.onGet("/v1/test/getcrumb").respond(200, "crumb1")`,
  `YFinance.builder().transport(fake).cache(...).maxRetries(0).build()`.

## Testing Strategy
- **Renderer unit tests**: hand-built specs and rows. They cover alignment, NaN and null per
  format, CSV quoting, JSON value types, truncation and colour.
- **Command golden tests**: `CliRunner` runs `new CommandLine(root).execute(args)` with a
  `ClientFactory` that builds the client over `FakeTransport` and the library's fixtures. It
  captures stdout, stderr and the exit code, and compares them with
  `src/test/resources/golden/<command>/<case>.<format>`. Settings are fixed: width 120, no colour,
  zone stays exchange. `-Dgolden.update=true` rewrites the golden files.
  - Each leaf command gets normal, empty and error cases in `table` and `json`. CSV gets one case
    per output shape (list, record, dynamic).
  - A coverage-guard test walks the picocli command tree and fails if any leaf command has no
    golden directory.
- **Exit-code mapping**: one table-driven test, each exception type → code and stderr line.
- **Native**: `-Pnative test` in PR CI on Linux x64. The release runs an offline smoke check
  (`--version`, `--help`) on all 4 targets. A nightly live job runs the Linux native binary
  against Yahoo and checks JSON shape, never exact values.
- No UI e2e tests (not applicable).

## Solution Overview
- **One Maven module**, Java 25, `./mvnw`. It is a named JPMS module `io.github.andreygrigoriev.yfin.cli`
  that `requires io.github.andreygrigoriev.yfin`, `info.picocli` and `com.fasterxml.jackson.core`.
  The compiler enforces that the CLI uses only exported library API. If something is missing,
  fix it in the library.
- **picocli**, with the `picocli-codegen` annotation processor generating the native-image
  reflect config for the command classes. That leaves no hand-written metadata in the CLI.
- **Output through explicit column specs** (`Spec<T>` made of `Column<T>`), declared as Java
  constants per model. One spec feeds the table, CSV and JSON renderers. No reflection and no
  Jackson databind: JSON is written with the streaming `JsonGenerator`.
- **Verb-first commands**, with parent commands only for families (`financials`, `holders`,
  `estimates`, `calendar`). `events SYM` is the per-ticker calendar. `calendar
  earnings|ipo|splits` is market-wide.
- **`--format` is never inferred.** The default is `table`. A TTY only changes styling.
- **Errors** are mapped once, in an `IExecutionExceptionHandler`, to fixed exit codes.
- **Release** runs entirely in GitHub Actions on a `vX.Y.Z` tag: a 4-target native matrix,
  tarballs, `SHA256SUMS`, the GitHub release, and a push to the tap. The only secret is
  `TAP_TOKEN`.

## Technical Details

### Global options (root command, inherited)
`--format table|csv|json` (default `table`), `--no-color`, `--no-cache`, `--timeout DURATION`,
`--retries N`, `--verbose`, `--version`, `--help`.

### Output model
- `Column<T>(String name, Function<T, ?> value, Kind kind)`. `name` is snake_case and is used as
  the JSON key, CSV header and table header.
- `Kind`: `TEXT`, `INTEGER`, `DECIMAL(scale)`, `PERCENT`, `DATE`, `TIMESTAMP`.
- `Spec<T>`: an ordered list of columns. `Spec.dynamic(List<Column<T>>)` is built at runtime for
  period-column data (statements, valuation).
- `Output.list(Spec<T>, List<T>)` and `Output.record(Spec<T>, T)`. For several symbols, a
  `Symbol<T>(String symbol, T value)` wrapper spec adds a leading `symbol` column.

| | table | csv | json |
|---|---|---|---|
| NaN / null | `—` | empty | `null` |
| INTEGER/DECIMAL | humanised (`1.23M`) | raw | number |
| PERCENT | `12.34%` | raw fraction | number |
| DATE | `2026-10-18` | ISO | ISO string |
| TIMESTAMP | `2026-10-18 09:30` exchange zone | ISO with offset | ISO string |
| list | aligned rows | header + rows | array of objects |
| record | two columns | `field,value` | object |

- TTY check: `System.console() != null && System.console().isTerminal()`. On a TTY: colour
  (green/red on `change` columns, off with `NO_COLOR` or `--no-color`), truncation of TEXT to
  `$COLUMNS` (default 120), right-aligned numbers. Off a TTY: no colour, no truncation.
- Empty result: table prints nothing (plus `no data` on stderr on a TTY), CSV prints the header,
  JSON prints `[]` or `{}`. Exit 0.

### Exit codes
| Code | Cause |
|---|---|
| 0 | success, including an empty result |
| 1 | unexpected exception (stack trace only with `--verbose`) |
| 2 | usage / conversion error (picocli) |
| 3 | `YFSymbolNotFoundException` |
| 4 | `YFRateLimitException` |
| 5 | `YFAuthException` |
| 6 | `YFTransportException` |
| 7 | `YFDataException`, `YFDownloadException` |
| 130 | interrupted |

The stderr line format is `yfin: <symbol>: <reason>`. `--verbose` adds the cause chain. With
several symbols, successful rows still print, each failure gets a stderr line, and the exit code
is that of the first failure.
